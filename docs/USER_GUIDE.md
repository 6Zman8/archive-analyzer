# 압축파일 검사기

압축파일 검사기는 ZIP·CBZ·RAR·7z 안의 이미지들을 읽어 대량의 중복 후보를 찾고 검토하는 Windows 프로그램입니다. 검사는 원본을 바꾸지 않으며, 기존 검사 DB를 그대로 재사용해 페이지 관계·판본 분석·추천·검토 기록을 추가합니다. 직접 선택한 파일은 격리 버튼으로 옮길 수 있고, 격리된 파일은 파일 또는 그룹 단위로 Windows 휴지통에 이동할 수 있습니다.

## 실행파일 사용 순서

추천 항목을 직접 정하려면 검토 화면 상단 `추천 기준 설정`에서 `사용자 우선순위`를 고르세요. 항목을 위/아래로 이동하고 체크를 끄면 제외합니다. 위 항목이 동급일 때만 다음 항목을 비교하며, 설정은 저장됩니다. `언어 → 용량`이면 한국어를 먼저, `용량 → 언어`이면 큰 파일을 먼저 추천합니다. 기존 엄격 비교로 되돌릴 수도 있습니다. 직접 기록한 검토 상태는 추천 갱신으로 덮어쓰지 않습니다.

1. 다운로드한 `ArchiveAnalyzer.exe`를 더블클릭합니다.
2. 이미 검사가 끝났다면 폴더를 다시 고르지 않고 `저장된 결과 열기`를 누릅니다. 가장 최근 완료 결과가 열리며 검사 화면은 숨겨집니다. 검토 화면의 `검사 화면` 버튼으로 돌아옵니다.
3. 새 폴더를 검사할 때만 `폴더 선택` 후 `검사 시작`을 누릅니다. 중단 뒤 같은 폴더를 다시 검사하면 바뀌지 않은 파일과 완료 단계는 재사용됩니다.

   검사 화면의 막대는 **현재 표시된 작업의 처리 비율**입니다. 대표 이미지 검사는 처리한 파일 수와 현재 파일의 검사 장수(최대 7장)를 표시합니다. 이어지는 `후보 비교 자료 준비`는 자료 읽기, 유효성 확인, 이미지 지표별 후보 쌍 비교를 구분해 각각 실제 처리 수/전체 수와 백분율을 표시합니다. 다음 작업으로 넘어가면 작업명과 분모가 함께 바뀝니다. 완료 시 막대는 100%로 남고 완료 결과를 표시합니다.
4. 후보 화면에서 검색·정렬·필터, 여러 그룹 선택, 두 파일 미리보기를 사용합니다. 파일·그룹 목록의 행이나 주변 빈 공간에서 마우스를 끌면 여러 항목이 선택됩니다. 그룹에는 `전체선택` 버튼이 있습니다. 미리보기 위의 마우스 휠을 아래로 돌리면 다음 페이지, 위로 돌리면 이전 페이지입니다. 열 제목의 ▾를 누르면 정렬과 값 검색·체크 목록이 열립니다. 숫자는 목록에서 고르거나 이상/이하 범위를 입력합니다. 신뢰도는 소수점 세 자리로 표시하며 열 폭은 저장됩니다.
5. 그룹을 선택하고 `이미지 정밀분석`을 누르면 언어 OCR과 컬러 판본을 확인하고 추천을 갱신합니다. 완료된 캐시를 재사용합니다. `고급 분석`에는 실제 페이지 지문으로 합본·개별권·부분 포함을 확인하는 페이지 포함 관계 분석과 판본 차이 분석이 있습니다. 모자이크는 이미지 분석 대상에서 제외하고 파일명 표기만 표시합니다. 모자이크·컬러 판정 불가는 추천을 막지 않습니다.

미리보기는 `두 파일 함께 넘기기`, `좌우 교환`, `가로 / 세로 배치`, `확대 / 복귀`를 지원합니다. 칸 크기에 맞춰 비율을 유지하며 확대·축소합니다. 이미지 크기가 화면 배치를 바꾸지 않도록 분리했고, 최근 4개 페이지(각 긴 변 최대 2048픽셀)를 메모리에 보관해 창 크기 변경 때 압축파일을 다시 읽지 않습니다. 분석·파일 작업 버튼은 칸 폭에 맞춰 배치합니다.
6. 파일을 직접 확인하려면 `탐색기에서 위치 열기` 또는 `반디뷰로 열기`를 사용합니다. 파일 목록에서 우클릭하면 해당 파일의 Windows 탐색기 우클릭 메뉴가 그대로 열립니다.
7. 파일별로 `보존`, `제거 후보`를 선택합니다. 추천은 `추천값 일괄 적용`으로 기록할 수 있고, `검토결과 일괄작업`으로 제거 후보를 격리합니다. 직접 내린 판정은 추천값으로 덮어쓰지 않습니다.
8. 격리 폴더는 다음 실행에도 저장됩니다. 파일을 바로 격리하려면 `격리 폴더 선택` 후 원하는 파일을 고르고 `선택 파일 격리` 또는 Delete를 누릅니다. 미리 제거 후보를 누를 필요가 없습니다. 격리된 파일도 미리보기, 탐색기 위치 열기, 반디뷰 열기를 계속 사용할 수 있습니다.
9. 격리된 파일은 `선택 파일 되돌리기` 또는 `선택 그룹 격리 되돌리기`로 복원합니다. `선택 그룹 휴지통 이동`과 `선택 파일 휴지통 이동`은 Windows 휴지통에 보냅니다. 휴지통 이동 뒤 복원은 Windows 휴지통에서 합니다. 휴지통을 사용할 수 없으면 실패로 보고하며 영구 삭제로 우회하지 않습니다.
10. `후보 그룹`, `검토됨`, `격리됨`, `휴지통·제거 이력`, `문제 파일` 탭으로 작업 상태를 구분합니다. 모든 파일의 검토가 끝나면 검토됨, 격리 파일이 있으면 격리됨, 격리 파일 없이 삭제 기록이 있으면 제거됨으로 그룹이 이동합니다. 각 그룹 안에는 비교와 이력 확인을 위해 나머지 파일도 표시됩니다.

추천은 페이지·언어·해상도·용량과 명시된 모자이크 속성을 비교합니다. 용량과 수정 시각, 언어와 페이지 수처럼 기준이 엇갈리면 검토 필요로 남깁니다. 다른 조건이 모두 동급이면 제목 형식을 먼저 비교하고, 제목 형식도 같으면 수정 시각을 비교합니다. 완전히 동일한 내용도 같은 제목/시간 순서를 사용합니다. 언어 미상·추정은 기본 추천을 막지만 모자이크·컬러 판정 불가는 막지 않습니다. 풀컬러·흑백 판본 분리는 유지합니다.

한글 제목은 한국어(추정), 언어 표시가 없는 다른 제목은 일본어(추정), 모자이크 표기가 없으면 유모(추정)로 표시합니다. `추정값 일괄 적용`을 선택하면 추정 언어로 추천을 계산하고 확인 후 검토에 기록합니다. 언어 충돌, 수치 누락 및 기준 충돌은 계속 검토 대상입니다.

정밀분석을 마치면 저장된 분석 결과로 추천을 다시 계산합니다. 추천값을 일괄 적용하면 검토 상태도 갱신됩니다. 기존 후보 묶음 식별자와 사용자 검토 기록은 유지하며, 재열기와 캐시 재사용 시에도 유지됩니다.

이전 작업을 다시 검토하려면 `격리됨` 탭에서 그룹을 선택하고 `선택 그룹 격리 되돌리기`를 누른 뒤, `선택 그룹 검토 초기화`로 기존 판정을 검토 필요로 돌리세요. 복원과 초기화는 별도 동작이며 기존 작업 이력은 보존합니다. 여러 그룹은 Ctrl/Shift 또는 전체선택으로 고를 수 있습니다. 각 탭의 전체선택은 해당 탭에 표시된 그룹에 적용됩니다. 검토를 마쳐 그룹이 후보 탭을 떠나면 방금 그룹의 다음 후보가 자동 선택됩니다. 파일 정보는 요약/상세 열로 전환할 수 있고, 직접 비교 근거는 더블클릭하면 전문이 열립니다. 파일과 직접 비교 표는 4행이며 미리보기에는 목록 번호·파일명·경로·페이지가 표시됩니다.

CSV는 자동으로 만들거나 열지 않습니다. 후보 화면에서 사용자가 `후보 CSV 내보내기`를 눌렀을 때만 고른 위치에 생성됩니다. 스프레드시트가 파일명 등을 수식으로 해석하지 않도록 위험한 시작 문자(`=`, `+`, `-`, `@` 및 제어 문자)가 있는 텍스트에는 작은따옴표를 앞에 붙입니다. CSV를 일반 텍스트로 읽는 도구에서는 이 표시가 보일 수 있으며 원본 파일명과 DB는 바뀌지 않습니다. 분석 DB는 원본 폴더 밖의 Windows 사용자 데이터 폴더에 저장됩니다.

다른 드라이브로 격리하거나 복원할 때 최종 복사본 확정 전에는 취소할 수 있습니다. 확정 뒤 들어온 취소는 현재 파일의 이동·기록을 마친 다음 적용합니다. 권한·디스크 오류로 양쪽에 파일이 남으면 `격리 진행·복구 대기` 기록을 유지하며 어느 복사본도 자동으로 삭제하지 않습니다. 이 경우 두 경로와 오류를 확인해 수동으로 해소해야 하며, 파일 상태가 해소된 뒤 결과를 다시 열면 기록을 대조합니다. 과거에 이미 FAILED로 기록된 항목을 일괄 변경하지 않습니다.

현재 지원 확장자는 ZIP, CBZ, RAR, 7z입니다. ZIP/CBZ는 프로그램이 직접 읽고 RAR/7z는 설치된 7-Zip으로 읽습니다. 실제 7z 표본은 검증했지만 실제 RAR 표본은 아직 검증하지 못했습니다. 실행파일 사용에는 Python 설치가 필요하지 않습니다.

## 개발자용 설치와 CLI

PowerShell에서 이 저장소로 이동한 뒤 실행합니다.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

7z와 RAR을 조사하려면 기본 경로 `C:\Program Files\7-Zip\7z.exe`에 7-Zip이 설치되어 있어야 합니다. 다른 위치라면 `scan`에 `--seven-zip "D:\도구\7z.exe"`를 추가합니다.

### 실행파일 빌드와 패키지 테스트

빌드는 프로젝트 `.venv`의 Python 3.13과 고정된 OCR·패키징 의존성만 사용합니다. OCR 모델과 사전은 빌드 때 검증해 실행파일 안에 넣으며, 실행 중 인터넷에서 내려받지 않습니다. 같은 대상이 이미 있으면 덮어쓰지 않고 중단합니다.

```powershell
pwsh -NoProfile -File .\tools\build_windows_exe.ps1 -Name '압축파일 검사기'
$env:ARCHIVE_ANALYZER_PACKAGED_EXE = (Resolve-Path '.\dist\final\압축파일 검사기.exe').Path
.\.venv\Scripts\python.exe -m pytest -o addopts=-ra -m packaged tests\integration\test_packaged_v1.py
```

패키지 확인용으로는 실행파일에 `--packaged-smoke <복사한-DB>`를 전달할 수 있습니다. 이 경로는 저장된 결과와 DB migration, 내장 OCR 자원만 확인하며 기록된 원본 폴더를 다시 읽지 않습니다.

### 안전한 CLI 기본 사용법

처음에는 실제 보관 폴더 전체가 아니라 별도로 복사한 작은 표본 폴더로 검증하십시오. 다음 예에서 DB와 보고서는 반드시 스캔 루트인 `D:\복사한-테스트-자료` 밖에 둡니다.

```powershell
.\.venv\Scripts\archive-analyzer.exe scan "D:\복사한-테스트-자료" --db ".\archive-analyzer.db" --workers 2
.\.venv\Scripts\archive-analyzer.exe status --db ".\archive-analyzer.db"
.\.venv\Scripts\archive-analyzer.exe report --db ".\archive-analyzer.db" --format csv --output ".\scan-report.csv"
.\.venv\Scripts\archive-analyzer.exe report --db ".\archive-analyzer.db" --format json --output ".\scan-report.json"
```

`--workers`는 1~8만 허용합니다. `scan`에는 루트를 반드시 명시해야 하며, 프로그램이 임의의 폴더를 자동 스캔하지 않습니다.

### CLI 중단과 재개

`Ctrl+C`로 중단하면 실행 상태가 `INTERRUPTED`로 저장되고 종료 코드 130을 반환합니다. 같은 루트와 DB로 `scan`을 다시 실행하면 미완료 작업을 복구해 이어서 처리합니다. 이미 정상 인덱싱되었고 크기와 수정 시각이 변하지 않은 아카이브는 재판독하지 않고 `reused`로 집계합니다. 손상 또는 암호화 상태였던 파일은 다음 실행에서 다시 확인합니다.

같은 DB에 `scan` 두 개를 동시에 실행할 수 없습니다. 실행 중에도 `status`와 `report`는 읽기 전용 SQLite 스냅샷으로 조회할 수 있습니다.

### CLI 결과 상태와 오류

콘솔 요약에는 `discovered`, `reused`, `indexed`, `skipped`, `failed`가 표시됩니다. 보고서의 주요 상태는 다음과 같습니다.

- `INDEXED`: 목록 인덱싱 완료
- `SKIPPED`: 안전 정책에 따라 건너뜀(예: `ENCRYPTED_UNSUPPORTED`)
- `FAILED`: 판독 실패(예: `CORRUPT_ARCHIVE`, `SEVEN_ZIP_NOT_FOUND`, `SEVEN_ZIP_FAILED`)
- `MISSING`: 완전한 후속 탐색에서 이전 파일이 더 이상 발견되지 않음
- `PENDING`: 아직 완료되지 않은 작업

현재 기록되는 오류 코드에는 `ENCRYPTED_UNSUPPORTED`, `CORRUPT_ARCHIVE`, `UNSUPPORTED_FORMAT`, `ACCESS_DENIED`, `FILE_NOT_FOUND`, `CHANGED_DURING_SCAN`, `SEVEN_ZIP_NOT_FOUND`, `SEVEN_ZIP_FAILED`, `ARCHIVE_LIMIT_EXCEEDED`, `PATH_TOO_LONG`, `DISCOVERY_ERROR`, `ARCHIVE_IO_ERROR`, `OUTSIDE_SCAN_ROOT`, `PATH_KEY_MISMATCH`가 있습니다. DB 자체 오류는 개별 보고서 행이 아니라 명령 종료 코드 1과 안정된 콘솔 메시지로 알립니다. 개별 아카이브의 암호화·손상은 해당 파일만 건너뛰거나 실패로 기록하며 나머지 스캔은 계속합니다. 7-Zip 자체가 필요한데 없으면 RAR/7z 파일이 `SEVEN_ZIP_NOT_FOUND`로 기록됩니다.

한 아카이브가 비정상적으로 많은 메모리를 차지하지 않도록 ZIP/CBZ 중앙 디렉터리 레코드(디렉터리 레코드 포함)를 최대 50,000개, 7-Zip이 출력한 디렉터리 제외 항목을 최대 50,000개까지만 처리합니다. ZIP 중앙 디렉터리와 7-Zip 목록 출력은 각각 최대 32 MiB이며, 7-Zip 출력은 프로세스가 실행되는 동안 이 한도에서 수집을 중단하고 프로세스를 종료합니다. 한도를 넘으면 원본을 변경하지 않고 해당 아카이브를 `ARCHIVE_LIMIT_EXCEEDED`로 기록한 뒤 다른 파일을 계속 처리합니다.

압축파일 안의 ZIP/CBZ/RAR/7z는 `NESTED_ARCHIVE` 항목으로만 기록하고 열거나 재귀 분석하지 않습니다. 내부 항목은 SQLite의 `archive_entries`에 저장됩니다. 재분석 지점, 심볼릭 링크, 정션은 따라가지 않습니다.

실제 7z 파일 판독은 7-Zip 24.09로 검증했습니다. 실제 RAR 표본은 현재 범위에 제공되지 않아 `RAR_REAL_FILE=NOT_VERIFIED_NO_SAMPLE`이며, RAR 지원을 실제 자료에서 검증 완료했다고 간주하면 안 됩니다.

### CLI 종료 코드

- `0`: 명령 완료. 개별 아카이브의 `SKIPPED` 또는 `FAILED`는 보고서에서 확인합니다.
- `1`: DB, 파일 시스템, 동시 스캔 또는 실행 중 오류
- `2`: 잘못된 인자 또는 안전 경계 위반
- `130`: 사용자가 `Ctrl+C`로 스캔 중단

### 경로 안전과 DB 백업

DB는 스캔 루트 내부에 둘 수 없습니다. SQLite 연결 전에 요청한 lexical 경로와 canonical 경로 양쪽에서 기존 DB와 `<DB>-wal`, `<DB>-shm`, `<DB>-journal`을 `lstat`으로 확인합니다. symlink, broken symlink, Windows reparse point, 일반 파일이 아닌 경로, 하드 링크 수가 2개 이상인 일반 파일 중 하나라도 발견되면 `scan`, `status`, `report`를 모두 보수적으로 거부하고 종료 코드 2를 반환합니다. 보고서도 DB 파일 자체나 그 하드 링크일 수 없고, DB에 기록된 모든 스캔 루트 밖에 있어야 합니다. 별도 로그 파일 옵션은 없으며, 향후 로그를 추가하더라도 소스 루트 밖에 두어야 합니다. 이 제한은 프로그램 생성물이 탐색 대상에 섞이거나 원본을 덮어쓰는 일을 막습니다.

SQLite의 정상 동작에 따라 DB 옆에는 `archive-analyzer.db-wal`과 `archive-analyzer.db-shm` 같은 sidecar가 생길 수 있습니다. 특히 실행 중인 스캔을 `status` 또는 `report`가 일관된 읽기 전용 스냅샷으로 조회할 때 SQLite가 이 파일을 사용할 수 있습니다. 단일 링크인 정상 sidecar는 그대로 지원하지만, 정적 alias나 다중 하드 링크 sidecar는 SQLite가 따라가거나 삭제할 가능성을 차단하기 위해 연결 전에 거부합니다. 프로그램은 이 sidecar를 소스 트리에 만들지 않으므로 DB와 같은 스캔 루트 밖의 디렉터리에 함께 두십시오.

이 방어의 위협 경계는 검사 시점에 이미 존재하는 정적 filesystem identity입니다. lexical 검사와 canonical 재검사 뒤 SQLite 연결까지의 매우 짧은 구간에서 별도 공격 프로세스가 파일을 교체하는 적대적 TOCTOU는 로컬 범위 밖입니다. 프로그램은 이를 막기 위해 sidecar를 임의 삭제하거나 운영체제 handle/VFS를 교체하지 않습니다.

백업 전에는 실행 중인 `scan` 명령이 끝났거나 중단되어 반환된 상태인지 확인한 다음 SQLite 백업 API를 사용하십시오. `status`는 최신 실행 요약을 확인하는 명령이며, 다른 프로세스의 실행 여부를 보장하는 잠금 조회 명령은 아닙니다. 아래 예는 실행 중인 스캔이 없을 때 일관된 별도 DB를 만듭니다.

```powershell
@'
import sqlite3

source = sqlite3.connect("archive-analyzer.db")
backup = sqlite3.connect("archive-analyzer-backup.db")
try:
    source.backup(backup)
finally:
    backup.close()
    source.close()
'@ | .\.venv\Scripts\python.exe -
```

DB 파일만 탐색기에서 복사하면 WAL에 아직 반영되지 않은 데이터가 빠질 수 있으므로 위 방식을 권장합니다. 백업 DB와 보고서도 스캔 루트 밖에 보관하십시오.

## 파일 작업 안전 범위

후보 판정은 사용자의 최종 판단을 대신하지 않습니다. 컬러·언어·편집/검열 가능성은 비교 근거로 표시합니다. 사용자가 직접 고른 격리·삭제를 이 추정만으로 차단하지 않습니다. 격리는 현재 파일 크기와 수정 시각, 최신 `제거 후보` 표시, 목적지 충돌 여부를 다시 확인합니다. 다른 드라이브로 옮길 때는 임시 파일로 청크 복사하고 크기와 SHA-256을 검증한 뒤에만 원본을 제거합니다. 중단은 파일 해시·복사 청크 사이에서 확인되며, 중간 종료 기록은 다음 실행 때 실제 원본과 격리본을 대조해 복구합니다. 목적지나 복원 위치의 기존 파일을 덮어쓰지 않습니다.

영구 삭제는 `QUARANTINED` 상태인 격리 사본만 대상으로 합니다. 원래 위치에 파일이 다시 생겼으면 중단하며, 격리 당시의 파일 크기·수정 시각·전체 SHA-256과 현재 파일이 모두 일치해야 삭제합니다. 삭제 시작과 완료 상태를 별도 기록해 비정상 종료 뒤에도 실제 파일 유무와 기록을 일치시키며, 복구 과정 자체에서는 파일을 삭제하지 않습니다.


### 2026-09-08 선택 및 후보그룹 제목 표시

- 후보그룹과 후보파일은 행 위에서 마우스를 누른 채 위아래로 끌어 여러 개를 선택할 수 있습니다. 빈 공간에서 사각형으로 선택하는 방식도 지원합니다. Ctrl을 누르고 끌면 기존 선택에 추가합니다.
- 후보그룹 제목은 모든 후보 파일명에서 정보를 모아 `[서클명(작가명)] 작품명 (속성명)`으로 표시합니다. 찾지 못한 항목은 `ㅁㅁㅁㅁ`이며 서로 다른 값은 `/`로 구분합니다. 이는 그룹 전체의 정보이므로 모든 파일이 같은 속성을 가진다는 뜻은 아닙니다.
- 선두 `[이름]`만 있는 파일명은 작가 단독 표기로 해석합니다. 원본 파일명은 바꾸지 않습니다. 기존 검사 결과를 다시 열면 새 표시가 적용되며 재검사는 필요 없습니다.


### 2026-09-09 복원 상태와 분석 후 추천

- 다운로드의 `압축파일 검사기.exe`를 실행하고 저장된 검사 결과를 여십시오. 폴더 전체를 다시 검사할 필요는 없습니다. 새 추천 기준은 결과를 열 때 재계산됩니다. 기존 검토 결과를 바꾸려면 그룹 선택 → `선택 그룹 검토 초기화` → 일반 추천 또는 `추정값 일괄 적용`을 사용하십시오.
- 복원·격리 기록을 실제 경로와 대조합니다. 원본 위치에 동일 파일이 확인되면 복원 완료, 양쪽에서 찾지 못하거나 파일이 달라졌으면 `파일 위치·격리 확인 필요`로 표시합니다. 후자를 복원 성공이나 삭제 완료로 간주하지 않습니다. 드라이브 접근 불가·삭제 작업 이력은 별도로 처리합니다.
- 페이지 관계·판본 분석은 선택 그룹 수와 새 분석 대상을 함께 표시하고 저장된 분석을 재사용합니다. 분석이 끝난 후 추천 갱신 단계를 따로 표시합니다.
- 언어·모자이크 정밀분석 뒤에는 추천에 필요한 컬러 판본을 확인하고 추천을 갱신합니다. 여전히 불확실하면 언어·모자이크·컬러 등 부족한 항목을 표시합니다.
- OCR 표본 측정에서 내부 연산이 이미 여러 CPU 코어를 사용함을 확인했습니다. 이번 수정에서는 추가 OCR 엔진 병렬화는 적용하지 않았습니다.

### 2026-09-09 A안 적용: 대량 후보 관리

- 다크 화면에서 왼쪽 후보 목록과 오른쪽 파일·비교 미리보기를 함께 사용합니다. 1280×860 기준 후보 약 21행, 파일/근거 각각 4행을 확보했습니다. 가운데 경계선으로 목록 폭을 조절할 수 있고 열 너비는 기존처럼 저장됩니다.

- 열 제목 ▾의 필터·정렬, 검색, Ctrl/Shift/드래그 다중 선택, 표시된 항목 전체선택을 유지합니다. `필터 해제`는 검색과 그룹 열 필터를 해제합니다. 표시/선택 개수를 목록 아래에 보여줍니다.
